# Predictioneering Research Factory — integrated prototype v0.2

**Scope:** This module connects (1) research puzzle intake, (2) local Zotero /
conflict-hazard bibliography screening, (3) guarded theory and research-design
specification, and (4) the existing statistical, predictive, and manuscript
prototype. It is **research-only** and never reads/modifies the forecasting
engine. **No API calls or paid Claude/OpenAlex/ACLED requests** are made by
`research.factory.pipeline`; raw licensed data never leave the local machine.

## Fast verification: completely synthetic

```bash
cd ~/predictioneering-research-test
git pull --ff-only
P="$HOME/.venvs/predictioneering-research/bin/python"
"$P" -m pip install -r research/requirements.txt
"$P" -m unittest discover -s research/tests -q
"$P" -m research.factory.pipeline demo
```

The demonstration exercises a private, synthetic study and reports whether
estimation, temporal OOS evaluation, draft writing and QC succeed. It cannot
pass human-novelty or real-data publication gates. The output is under
`research/projects/factory_runs/factory_pipeline_demo/` (gitignored).

## Progress a real puzzle (human gates are mandatory)

```bash
# Option A: use an existing 16-hex puzzle card generated by the existing
# `python -m research.factory ingest` intake, after `approve <ID>`.
"$P" -m research.factory list

# Option B: register a researcher-written JSON puzzle WITHOUT a Claude call.
"$P" -m research.factory.pipeline register /path/to/puzzle.json
# This prints a 16-character ID and creates a PENDING card.
"$P" -m research.factory show PUZZLE_ID
"$P" -m research.factory approve PUZZLE_ID

# Populate reusable project folders, query the LOCAL Zotero/hazard database,
# prepare a hypothesis and theory/design worksheet, then STOP at the novelty gate.
"$P" -m research.factory.pipeline run PUZZLE_ID
# If a local index exists elsewhere:
"$P" -m research.factory.pipeline run PUZZLE_ID --db /path/to/research_library.sqlite3
```

The runner uses existing `research.factory.library_review` with
`external=False, retrieve_only=True`, so the first pass reads local indexed
**bibliographic metadata, not the original PDFs**, and does not call a model.
This is a source shortlist, **not** a verified literature gap.

Read `research/projects/factory_runs/pPUZZLE_ID/literature_candidates.json`
(the `id` fields are exact source IDs). Read relevant original papers yourself,
then, ONLY if independently justified, record a human decision:

```bash
"$P" -m research.factory.pipeline approve PUZZLE_ID \
  --reviewer 'Your reviewer label' \
  --notes 'A substantive account of which original papers were read, how their models overlap, and what remains genuinely different.' \
  --source-id 'EXACT_SOURCE_ID_FROM_CANDIDATES' \
  --full-text-checked
```

The command records an **attestation**, not machine verification. It never
silently approves novelty or accepts nonexistent source identifiers.
If novelty fails, do **not** approve; reject the intake card or revise into a
new puzzle. A changed original card, research question, mechanism or hypothesis
cannot silently inherit an earlier novelty approval.

Next edit the private `analysis_spec.json` in the project's folder. The factory
prepopulates the proposed mechanism and supplied H1 but deliberately leaves the
outcome, treatment, time column, estimation method, outcome family and CSV path
unset. Decide these from the actual data and identification logic. Supported
choices remain association/DiD/RDD with gaussian/binomial/poisson GLMs.
The underlying `prototype.validate_spec` checks columns and flags missing
data and invalid designs. Examples are in `research/examples/factory_spec_template.json`.

Then run exactly the same command again:

```bash
"$P" -m research.factory.pipeline run PUZZLE_ID
"$P" -m research.factory.pipeline status PUZZLE_ID
```

When the human novelty decision, complete spec and private CSV are supplied,
the integrated pipeline invokes `prototype.run` automatically. It writes
`output/results.json`, `output/MANUSCRIPT_DRAFT.md`, `output/QC_REPORT.json`,
`output/replication_manifest.json`, `theory_workbook.md` and
`design_workbook.md`, with cached fingerprints and a private `workflow.json`.
Restarting unchanged inputs reuses the previous model; changed data/spec force
re-estimation. Failures preserve retryable state. No source CSV is copied into
the manuscript package.

## Batch mode

```bash
"$P" -m research.factory.pipeline batch --limit 30
```

This advances **already approved** puzzle cards to the next mandatory gate,
with local-only library queries and per-project status. It does not create an
automatic weekly cron job or ingest protected production logs by itself.
Unapproved puzzle cards are never analyzed.

## Honest limitations

This is an **integrated operational prototype**, not an autonomous publishing
machine. The theory worksheet is a defensible source-grounded *candidate*
scaffold, **not** a verified solved repeated game. The design and data mapping
must be supplied by a researcher; causal identification is not auto-proved.
Full-text novelty review, independent theory/causal checks, advanced robustness,
external replication, final manuscript review, true integration with weekly
forecast-log ingest, and any scheduling remain distinct unimplemented gates.
Only the association design has temporal OOS scoring; DiD/RDD OOS is explicitly
unimplemented. Do not call a paper published or publishable because code ran.
